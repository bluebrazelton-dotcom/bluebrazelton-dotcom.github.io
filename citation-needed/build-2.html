How it was built

I started Build 2 in Claude Code, with the Fable model, on October 13, the same day Build 1 closed, and it took fewer than five sessions. The difference was not the tool so much as the person using it: after six weeks with Build 1, I could finally express the project clearly, especially the game economy that had eaten so much of my time before. The brief fit on one page (one engine for every chapter, four kinds of buttons, a resource called Patience that drains when you click and refills when you rest, and a short list of joke rules), and its first line said nothing from the previous build’s folder was in scope. We balanced Chapter 1 in a spreadsheet and a small simulation before any code existed, and the brief told the agent to stop after Chapter 1 and show me, so most of my job was letting Claude Code run and answering a few questions here and there. I played the slice, the pacing got faster after that first playtest, and Chapter 1 was done on October 14.

What worked

This is the build where I finally got more activity into the game for the player. The Patience Game is not an idle game (that’s next!), and I had learned that if there is nothing for a player to do while the currency stacks up, they lose interest, so the brief gave every chapter four kinds of buttons to tap, hold, wait on, and submit, each with its own rhythm. The discipline held, too: the game does what the one-page brief asked for, and I have not found anything in it that the brief did not ask for. The upgrade jokes land because the brief limited them to one dry line each (the Planner is “Color-coded. The colors don’t mean anything yet.”), and setbacks are a two-second animation instead of a punishment.

Where the slop crept in

Very little slop crept in, because very little was allowed in; the bigger problem is the opposite of slop, since Build 2 is one chapter of a planned seven, and the end of Chapter 1 is exactly where I told it to stop and exactly where my own patience ran out. The game is called The Patience Game, and I see the irony. Two small leftovers made it into the public build. The first is a “Test: infinite Patience” link in the footer, a developer shortcut that should have been hidden, and I have left it there on purpose as an honest artifact of how the game was tested. The second is a gray box behind the flashcard sprite, which is a flaw, and it is also exactly the kind of tiny fix I could get obsessed with, hunting for more issues like it while the bigger ones wait. I have been in that car before, and I already know the radio presets are not the problem.
